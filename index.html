PDF/UA-2 from Typst: a working prototype

Typst can already make accessible PDFs to the PDF/UA-1 standard. This is an experiment to see what it would take to reach PDF/UA-2, the version for PDF 2.0, and whether a real document gets through a validator at the end.

Read this first. This is a prototype, and the code was written with Claude, an AI assistant. Nobody who knows the PDF specification well has reviewed it, nobody has tried the output in a screen reader yet, and equations are not done the way PDF/UA-2 requires. It is here to be looked at, not merged. Typst does not accept AI-written code, so none of this is offered to Typst as a pull request.

Result

Three documents, each exported as PDF 2.0 by Typst as it is today and as PDF/UA-2 by the prototype, then checked with veraPDF 1.30.3 against its PDF/UA-2 profile (1,728 rules).

The pages look the same in both. On the thesis sample, all 12,635 glyphs and shapes sit in exactly the same place. The difference is in the tags that assistive technology reads.

Passing veraPDF is not the same as conforming. PDF/UA-2 says mathematical expressions have to be given as MathML (clause 8.2.5.29). veraPDF does not check that, and the prototype only gives an equation a text description. All three documents contain an equation, so they pass the validator without fully conforming. A document with no maths in it does not have this problem.

How a document gets there

Typst lays the document out and decides what the tags are. krilla, the library it uses to write PDFs, turns that into the file. Both needed changes, shown in green.

Your document

Ordinary Typst source. Nothing changes here, apart from asking for ua-2.

Typst

Gives an id to anything that is pointed at, and says what each link, bookmark, contents entry and footnote refers to.

krilla

Writes those as structure destinations and Ref entries, uses the PDF 2.0 tag names, and marks the file as PDF/UA-2.

PDF 2.0 file

Looks identical on the page. A few per cent larger than plain PDF 2.0.

veraPDF

An independent validator checks 1,728 rules. It knows nothing about how the file was made.

Where krilla knows it cannot write something PDF/UA-2 needs, for example a link that leads to a bare position on a page, it stops with an error instead of writing a file that claims PDF/UA-2 and fails. It does not catch everything: a term list still exports and fails one rule.

The branch and the discussion are at krilla issue 449. The maintainer's view is that PDF/UA-2 needs someone with good knowledge of the PDF specification in the loop, and that review time is the bottleneck. I agree, which is why this page exists.

In Typst

  1. A ua-2 value for --pdf-standard.
  2. An id on each tag that something points at, with links, bookmarks and named destinations leading to it.
  3. Ref from each contents entry to its heading, and between a footnote and the link with its number.
  4. A figure that wraps a single table or image has no tag of its own, so a reference to it goes to the element inside.
  5. Tags inside an element with an alternative description are left out, so a reference to a sub-figure goes to the described figure.
  6. Citations link to the number of a bibliography entry, which has a location but no tag. Those go to the nearest enclosing element that has one, as does any other link to content without a tag.
  7. Loose inline content in a block quote, or directly in the document, goes in a paragraph. Typst uses a span with block placement there, which ISO 32005 does not allow.
  8. A caption cannot sit in a Div under the document, because the Div does not count as its parent. The prototype wraps a figure and its caption in a Sect.

Items 4 to 7 only showed up when real documents were run through it.

What it doesn't show

Passing a validator is necessary, but it is not the same as being right. These need a person.

  • Nobody has tried it in a screen reader. That is the real test of an accessibility change, and it has not been done.
  • Equations do not conform. PDF/UA-2 requires MathML for mathematical expressions, as tags or as a file attached to the formula (clause 8.2.5.29). Neither krilla nor the prototype can write that yet. This is the largest gap, and veraPDF is silent about it.
  • The standards were read late. The work went by veraPDF's rules first. ISO 14289-2 and ISO 32000-2 were read afterwards, and only the clauses this touches. That reading confirmed most of it and changed three things: a named destination that leads to a tag is now written the way ISO 32000-2 describes (12.3.2.4), a go-to action's structure destination is always an array (table 202), and an outline is no longer required, because PDF/UA-2 only recommends one (8.12.2).
  • Two things the standard asks for are not done. A link to somewhere in the same document should be tagged Reference, not Link (8.2.5.20), and the dots that lead to a page number in a contents list have to be marked as artifacts (8.2.5.8). I have not checked what Typst does with the second.
  • Some choices are allowed but may not be right. PDF/UA-2 says a caption has to be a child of the element that encloses what it captions (8.2.5.27), so wrapping a figure and its caption is right. But the prototype uses Sect for the wrapper, which means a section in the document's hierarchy. Aside, or putting the caption inside the Figure, is probably closer. Sending a citation to the nearest enclosing element is also my guess, not something the standard spells out.
  • veraPDF has no rule for some things. It does not check that a footnote's number points at the note, only that the references which exist match up. It cannot tell whether alternative text is any good or the reading order makes sense.
  • The code has shortcuts. Links split over two lines and footnotes that run on to the next page are handled but not covered by a test document. Term lists still fail.
  • It is three documents. Running a 373-page document found a bug that the 20-page one did not. More documents would find more.

Build it

You need Rust, and veraPDF if you want to check the output.

git clone --branch ua2-prototype https://github.com/Thenewmanator15/typst
cd typst
cargo build --release -p typst-cli

target/release/typst compile --pdf-standard ua-2 document.typ
verapdf --flavour ua2 document.pdf

A document needs a title, a language and alternative text on figures and equations, as it does for PDF/UA-1. If something cannot be made to conform, the export stops with an error that says what and where.
