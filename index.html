PDF/UA-2 from Typst: a working prototype

Typst can already make accessible PDFs to the PDF/UA-1 standard. This is an experiment to see what it would take to reach PDF/UA-2, the version for PDF 2.0, and whether a real document gets through a validator at the end.

Read this first. This is a prototype, and the code was written with Claude, an AI assistant. Nobody who knows the PDF specification well has reviewed it, and nobody has tried the output in a screen reader yet. It is here to be looked at, not merged. Typst does not accept AI-written code, so none of this is offered to Typst as a pull request.

Result

Three documents, each exported as PDF 2.0 by Typst as it is today and as PDF/UA-2 by the prototype, then checked with veraPDF 1.30.3 against its PDF/UA-2 profile (1,728 rules).

The pages look the same in both. On the thesis sample, all 12,635 glyphs and shapes sit in exactly the same place. The difference is in the tags that assistive technology reads.

Passing veraPDF is not the same as conforming. veraPDF checks 1,728 rules, but PDF/UA-2 asks for things it has no rule for. The clearest is that mathematical expressions have to be given as MathML (clause 8.2.5.29). The prototype now does that, but an earlier version did not and passed just the same.

How a document gets there

Typst lays the document out and decides what the tags are. krilla, the library it uses to write PDFs, turns that into the file. Both needed changes, shown in green.

Your document

Ordinary Typst source. Nothing changes here, apart from asking for ua-2.

Typst

Gives an id to anything that is pointed at, says what each link, bookmark, contents entry and footnote refers to, and makes MathML for each equation.

krilla

Writes those as structure destinations and Ref entries, attaches the MathML to its formula, uses the PDF 2.0 tag names, and marks the file as PDF/UA-2.

PDF 2.0 file

Looks identical on the page. A few per cent larger than plain PDF 2.0, more if it is mostly maths.

veraPDF

An independent validator checks 1,728 rules. It knows nothing about how the file was made.

Where krilla knows it cannot write something PDF/UA-2 needs, for example a link that leads to a bare position on a page, it stops with an error instead of writing a file that claims PDF/UA-2 and fails. It does not catch everything it cannot check, such as whether a formula that needs MathML has it. The prototype checks that itself.

The MathML is the same that Typst's HTML export makes. A reader can speak it, step through it or turn it into braille, which it cannot do with a sentence of description. With it, the description is no longer required for PDF/UA-2.

The branch and the discussion are at krilla issue 449. The maintainer's view is that PDF/UA-2 needs someone with good knowledge of the PDF specification in the loop, and that review time is the bottleneck. I agree, which is why this page exists.

In Typst

  1. A ua-2 value for --pdf-standard.
  2. An id on each tag that something points at, with links, bookmarks and named destinations leading to it.
  3. Ref from each contents entry to its heading, and between a footnote and the link with its number.
  4. A figure that wraps a single table or image has no tag of its own, so a reference to it goes to the element inside.
  5. Tags inside an element with an alternative description are left out, so a reference to a sub-figure goes to the described figure.
  6. Citations link to the number of a bibliography entry, which has a location but no tag. Those go to the nearest enclosing element that has one, as does any other link to content without a tag.
  7. Loose inline content in a block quote, or directly in the document, goes in a paragraph. Typst uses a span with block placement there, which ISO 32005 does not allow.
  8. A caption has to be a child of the element that encloses what it captions, and a Div does not count as that. The prototype wraps a figure and its caption in an Aside.
  9. MathML for each equation, from the converter that HTML export already has, handed to krilla with the Formula tag. It is only made when ua-2 is asked for, because it costs about as much as laying the equation out.
  10. A link to a place in the same document is tagged Reference, and only a link that leaves the document is a Link.
  11. A list of terms is marked as a description list, since its terms are labels.
  12. The filler between a contents entry and its page number is an artifact whatever it is made of, not only when it is the default row of dots.
  13. The number beside a numbered equation is marked as its label, not as part of the maths.
  14. A footnote says that it is a footnote, and a list says which bullet or numbering it uses.
  15. The bibliography is a section with the role doc-bibliography.
  16. Heading levels may skip, which PDF/UA-1 forbade and PDF/UA-2 deliberately allows.
  17. Each heading opens a section that runs to the next heading of the same or a higher level, so a reader can skip a whole section.
  18. The number of a numbered line is an Artifact element at the start of its line, not a loose mark in the margin.

Items 4 to 7 only showed up when real documents were run through it. Items 9 to 18 came from reading the standard, the last six from going through every clause of it. veraPDF has no rule for any of them: it passed the files before each change and after.

What it doesn't show

Passing a validator is necessary, but it is not the same as being right. These need a person.

  • Nobody has tried it in a screen reader. That is the real test of an accessibility change, and it has not been done.
  • The MathML has not been heard. Equations now carry MathML, and it matches what Typst's HTML export makes, but that export is itself marked experimental, and nobody has listened to it in a screen reader that reads MathML from a PDF. Support for that in readers is still thin. veraPDF has no rule for any of it.
  • The standard was read after the code, not before. The work went by veraPDF's rules first. I have since been through every clause of section 8 of ISO 14289-2, and the parts of ISO 32000-2 it points to. That changed how named destinations are written, dropped a requirement for an outline that PDF/UA-2 does not make, and added MathML and items 9 to 16 above. Most of the rest does not apply, because Typst cannot produce forms, media, redactions or ruby text.
  • Two things from that reading are not done. When an equation is given a written description, its number is not labelled, because Typst leaves out the tags inside anything that has a description. And only headings that sit directly in the document open a section; one inside a block or a column layout does not.
  • Some of it only a reader of the standard can check. veraPDF passed the files before items 9 to 18 and passes them after, so it says nothing about whether those are right. They rest on my reading of the clauses.
  • Some choices are allowed but may not be right. PDF/UA-2 says a caption has to be a child of the element that encloses what it captions (8.2.5.27). The prototype wraps a figure and its caption in an Aside. ISO 32005 does not allow an Aside in a table cell, a block quote or another Aside, so there it uses a Sect. I tried the alternatives there: Div, Part and NonStruct all fail, because they do not count as the caption's parent, and ISO 32000-2 does define Sect as a grouping of elements with regard to their hierarchy, so it is the right element of those that are allowed. The other way would be to put the caption inside the Figure, but a reader that speaks a figure's description skips what is inside it. Sending a citation to the nearest enclosing element is also my guess, not something the standard spells out.
  • veraPDF has no rule for some things. It does not check that a footnote's number points at the note, only that the references which exist match up. It cannot tell whether alternative text is any good or the reading order makes sense.
  • The code has shortcuts. Links split over two lines and footnotes that run on to the next page are handled but not covered by a test document.
  • It is three documents. Running a 373-page document found a bug that the 20-page one did not. More documents would find more.

Build it

You need Rust, and veraPDF if you want to check the output.

git clone --branch ua2-prototype https://github.com/Thenewmanator15/typst
cd typst
cargo build --release -p typst-cli

target/release/typst compile --pdf-standard ua-2 document.typ
verapdf --flavour ua2 document.pdf

A document needs a title, a language and alternative text on figures, as it does for PDF/UA-1. Equations no longer need a description, because they carry MathML. To be PDF/A-4 as well, ask for ua-2,a-4f: plain PDF/A-4 does not allow the attached MathML. If something cannot be made to conform, the export stops with an error that says what and where.
